# pi05 全量解冻：纯模型 Home20 34/60

日期：2026-10-10

这一页记录 pi05 在 Lab01-PnP-Home20 上到 **34/60** 的纯模型成绩，以及中间哪些改法没有抬高成功率。2026-10-05 的阶段表仍在 [`vla_home20_193.md`](vla_home20_193.md)；那里的 pi05 **12/60** 是更早的一版权重，仓库不要覆盖。

## 成绩

评测是纯模型。全程没有专家接管。协议是 Lab01-PnP-Home20：20 个固定方块位姿，手臂 `home`，夹爪起点 0.85，种子 1000 / 1001 / 1002，引用 `final_success`。相机是腕部和前方，俯视相机在数据里但不进这个模型。

| 种子 | 成功 | 抬起 | 闭合 | 掉落 |
|---|---:|---:|---:|---:|
| 1000 | 12/20 | 13 | 20 | 1 |
| 1001 | 11/20 | 13 | 19 | 2 |
| 1002 | 11/20 | 12 | 19 | 0 |
| 合计 | **34/60** | **38** | **58** | **3** |

漏斗合计：8 cm 内 60，4 cm 内 60，闭合 58，抬起 38，到盒子上方 37，抬起后松开 35，某拍已放入 34，最终仍在盒内 **34**，抬起后掉落 3。

同一协议上，ACT 6 维是 **53/60**，SmolVLA follow2 是 **51/60**，MolmoAct2 加长 20K 是 **39/60**。这版 pi05 超过了 MolmoAct2，还低于 ACT 和 SmolVLA。

另有一次数字也是 34/60：前方相机 10K 走到夹爪距方块 8 cm 且夹爪仍张开，然后由脚本专家完成抓取和放置，三次是 12/20、11/20、11/20。那次的抬起和放入来自专家。上面这张表是模型自己做完。专家再加一次重抓的 59/60 同样是专家分数，不记成模型成绩。

## 权重

Hub：[alexhegit/so101-simstudio-lab01-pnp-pi05-agent193-unfreeze](https://huggingface.co/alexhegit/so101-simstudio-lab01-pnp-pi05-agent193-unfreeze)

本地：`/tmp/lab01_pi05_front_unfreezeA2_15k/checkpoints/005000/pretrained_model`

目录名是 `005000`，因为每一段 5000 步都重新计数。这是第三段的权重，不是从零数到 1.5 万步的同一个优化器。

训练数据是 193 条，Hub：[alexhegit/so101-simstudio-lab01-pnp-agent-yaw-v4-actonly-follow2](https://huggingface.co/datasets/alexhegit/so101-simstudio-lab01-pnp-agent-yaw-v4-actonly-follow2)。磁盘上的 `observation.state` 仍是 15 维；训练只取前 6 维关节 `.pos`。

更早的 pi05 10K（俯视相机映射成 `front`，只训动作专家，Home20 **12/60**）仍在 [alexhegit/so101-simstudio-lab01-pnp-pi05-agent193](https://huggingface.co/alexhegit/so101-simstudio-lab01-pnp-pi05-agent193)。两个仓库不要混用。

## 怎么走到 34/60

起点都是 [`ant0nh/pi05_pnp_425_25k`](https://huggingface.co/ant0nh/pi05_pnp_425_25k)。数据始终是这 193 条，除非下表写了额外轨迹。成绩都是纯模型 Home20。

| 尝试 | 训练了什么 | 成功 | 抬起 |
|---|---|---:|---:|
| 10K，俯视映射成 front，只训动作专家 | 动作专家 | 12/60 | 15 |
| 前方相机重新训 10K，仍只训动作专家 | 动作专家 | **17/60** | 22 |
| 把成功的 8 cm 抬起片段蒸馏回去，视觉仍冻结 | 动作专家 | 10/60 | 13 |
| 从前方 10K 全量解冻 2500 步 | 视觉、语言、投影、动作专家 | 20/60 | 23 |
| 只解冻视觉、投影和动作专家，语言模型冻结 | 约 11 亿参数 | 17/60 | 23 |
| 用上一行 20/60 的模型录重抓整段，混进 193 再全量解冻 2500 步 | 全模型 | 19/60 | 21 |
| 从前方 10K 重新全量解冻 5000 步，批量 2 | 全模型 | 20/60 | **28** |
| 从上一行权重再训 5000 步，新优化器，批量 1 | 全模型 | **33/60** | 36 |
| 再训 5000 步，同一配方 | 全模型 | **34/60** | 38 |

冻结视觉时，多训、降低学习率、重抓后缀、闭合前片段、抓取窗加权、把开环从 50 步改成 10 步，都只让闭合变多，抬起停在 22 次附近。最好的冻结权重是前方相机 10K 的 **17/60**。把专家抬起片段蒸馏进这个冻结模型，掉到 **10/60**。

只解冻视觉塔和投影、语言模型继续锁住，停在 **17/60**。全量解冻 2500 步到 **20/60**，但相对前方 10K 是 12 个姿态从失败变成功、9 个从成功变失败，抬起只多 1 次。

从前方 10K 重新开一段更长的全量解冻之后，抬起先到 28/60，成功仍是 20/60。再开一段新的余弦、峰值学习率仍是 `2.5e-6`，成功到 **33/60**，抬起 36。同一配方再加 5000 步，成功 34、抬起 38。靠近、闭合、掉落和 33/60 那一版相同（60、58、3）。这一步已经停住。

重抓整段（靠近、第一次空夹、专家重抓、放入）按约 19% 混进 193，从 20/60 的权重接着训，得到 **19/60**。这条没有超过只训 193 的全量解冻，没有并进最终权重。

## 最后这一版的配方

| | |
|---|---|
| 初始化 | 上一段 33/60 的权重，不是从 `ant0nh` 重来 |
| 可训练参数 | 4,143,404,816，等于总参数 |
| `train_expert_only` | false |
| `freeze_vision_encoder` | false |
| 数据 | 193 条，不混重抓或蒸馏片段 |
| 相机 | `camera_wrist` → `wrist`，`camera_front` → `front` |
| 状态 / 动作 | 6 维绝对关节 `.pos`，`use_relative_actions=false` |
| 步数 / 批量 | 5000 / 1 |
| 学习率 | 峰值 `2.5e-6`，warmup 200，`decay_steps=5000`，末端 `2.5e-7` |
| 优化器 | 新开。不 `--resume` 已经走完的余弦 |
| `num_workers` | 0。全量解冻时 worker 大于 0 会在 CUDA 初始化之后卡死 |
| chunk / `n_action_steps` | 50 / 50 |
| dtype | bfloat16，梯度检查点开着 |

`decay_steps` 必须等于这次的 `--steps`。短于默认 30000 时，LeRobot 的余弦会把 warmup 和衰减再缩放一次，峰值就不是 `2.5e-6`。

三段 5000 步都是这个学习率。第一段批量 2，后两段批量 1。后两段的优化器都重新开始，不接着上一段已经衰减到 `2.5e-7` 的状态。

## 缺口

34/60 里没做成的，多数是闭合了但没有抬起：闭合 58，抬起 38。掉落只有 3 次。同一套 5000 步再训，成功从 33 到 34，抬起从 36 到 38，三个种子的波动和上一版同一量级。

再加步数不是下一步。若还要抬这版模型，补的应是它自己空夹的轨迹，而不是前面已经试过的重抓整段或冻结蒸馏片段。
